# Review — react--starry-sky

A React component wrapping `@tsparticles/basic` to render an animated starfield/particle background, with an optional
CSS gradient backdrop and configurable density/speed/size options.

## Findings

- **G6-P16-01** (Minor) — `useEffect` dependency array is `[id]` (`module/src/index.tsx:169`), but the effect body
  captures `options` (derived fresh every render from `{ ...DEFAULTS, ...props }`, `module/src/index.tsx:120-123`) to
  build `optionsⵧtsp`. Since `id` never changes across re-renders (from `useId()`), the effect never re-runs after mount
  even if the caller passes new `density`/`move__speed`/etc. props on a later render — the particle system's options are
  effectively "set once" and prop changes after mount are silently ignored. If `Options` are meant to be reactive/config
  props, this is a stale-closure bug; if presets are truly meant to be immutable per mount, this should be documented
  (e.g. via a comment or a lint-suppression) since the ESLint `react-hooks/exhaustive-deps` rule would otherwise flag
  it.
- **G6-P16-02** (Minor) — Async race/cleanup pattern: on unmount, `tempState.active` is flipped to `false` and, if a
  container promise already exists, `.then(container => { container.stop(); container.destroy(true) })` runs
  (`module/src/index.tsx:154-167`). However if unmount happens strictly _between_ `ೱLIB_INIT.then(...)` starting and
  `tsParticles.load(...)` resolving — i.e. `tempState.ೱcontainer` was assigned synchronously inside the `.then` callback
  (line 145) right before the outer `if (!tempState.active) return` check in the _same_ callback runs — the guard at
  line 143 does correctly bail before calling `tsParticles.load`. So this specific race looks handled correctly;
  flagging as reviewed rather than a bug. No actual issue found here — noting it because this is exactly the kind of
  async-effect-cleanup pattern the task asked to scrutinize closely.
- **G6-P16-03** (Nit) — `move: { enable: options.move__speed > 0, ... }` (line 80) means with the default
  `move__speed: 0`, particles never move — consistent with `DEFAULTS`, just noting the "Move" story overrides it, so
  default rendering is a static starfield (probably intentional).
- **G6-P16-04** (Minor) — `background__color = "black" // TODO mid from gradient` (line 173) is a hardcoded fallback
  with an open TODO; when `background_type !== "transparent"`, the plain `backgroundColor` is always set to `"black"`
  even though a gradient is also applied on top via the `background` shorthand — the flat `backgroundColor` becomes
  visually irrelevant (overridden by `background`) except as a flash-of-black-before-gradient-paints fallback, but that
  intent isn't stated.
- **G6-P16-05** (Nit) — `use(ೱLIB_INIT)` (line 117) is called unconditionally on every render before hooks like
  `useId`/`useEffect`. This is valid per React's newer `use()` hook rules (it can be called conditionally, unlike other
  hooks) but since `ೱLIB_INIT` is a single module-level promise that resolves once, `use()` here mainly just suspends
  the very first render tree until plugins are loaded — worth a one-line comment since this is a less common hook and
  its purpose (block first paint on plugin init) isn't obvious from the code alone.
- **G6-P16-06** (Minor) — No tests exist (mocha/chai or vitest) despite meaningful branch logic in
  `getTsParticlesOptions` and the cleanup/race handling in the effect — this is the most animation/lifecycle-heavy of
  the reviewed packages and would benefit most from at least a smoke test around mount/unmount not throwing and calling
  `destroy`.
- **G6-P16-07** (Nit) — `MoveDirection` type import from `@tsparticles/engine` is used only as the type of
  `move__direction`; fine, just noting the whole `@tsparticles/*` dependency surface is sizable for a component this
  small — no action needed, just context for the "outdated deps" check (versions weren't independently verified against
  upstream latest in this review; recommend a `pnpm outdated` check for `@tsparticles/*` periodically since that library
  iterates quickly).

No `dangerouslySetInnerHTML` or unsafe attribute injection — the only DOM-adjacent behavior is tsParticles being handed
a `div#{id}` to manage internally, and the `id` is generated by React's `useId()`, not user input.

No OOP/class usage in this package's own code — functional component, consistent with project conventions.
