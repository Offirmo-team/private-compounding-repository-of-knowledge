# Review: plugin--offirmo

The largest/most central plugin: seeds default workspace globs, pins shared dependency version overrides, adds
cross-cutting dev dependencies/scripts to every package, and writes a family of README.md files plus a generated bash
aliases script.

## Findings

- **G10-P1-01 (Major, security — unescaped shell interpolation)** — In the `_aliases()` IIFE, `.monorepo/bin/aliases.sh`
  is generated by interpolating node metadata directly into a single-quoted bash string:
  `alias mono.<namespace>.<name>='cd ...; mise install; git--offirmo.sh; cd <relative_path>/'` None of the interpolated
  values (`namespace`, `name`, path) are escaped. Since these values are sourced from local package/directory names
  (developer-controlled, not attacker-controlled/external input), actual exploitability is low today — but it's a latent
  fragility: any package or namespace name containing a single quote would break or corrupt the generated script, and
  the pattern should not be copied to a context where the inputs _could_ be attacker-influenced (e.g. names from
  unpackaged/external sources). Worth hardening (e.g. shell-quoting the interpolated segments) defensively.
- **G10-P2-01 (Minor, cross-cutting note — not itself a bug)** — `onꓽnodeⵧrefine` unconditionally adds `npm-run-all`,
  `@monorepo-private/scripts`, `@monorepo-private/assert`, `config--mocha`, vitest, chai, sinon, `@types/sinon`, mocha,
  `@types/mocha`, `@types/node` to every js/ts package outside `"0-meta"`. This is the root cause of the repo-wide
  pattern (observed across all 24 packages in this review) of every package.json carrying both legacy mocha/chai/sinon
  AND vitest devDependencies. Per the project's stated migration plan (mocha/chai tolerated on existing code, vitest for
  new tests) this is expected/fine, but it's worth being aware this single plugin is what drives it everywhere, in case
  the intent is eventually to stop injecting the legacy deps by default.
- **G10-P3-01 (Minor)** — `onꓽnodeⵧrefine` for "monorepo" contains a ~15-line commented-out block of legacy scripts
  (bolt clean/build/test, manypkg check/fix, serve/ngrok) marked `/* TODO re-add scripts ... */` — significant dead code
  left as a comment rather than tracked elsewhere (e.g. an issue).
- **G10-P4-01 (Nit)** — Multiple acknowledged TODOs: `// TODO 1D auto create packages`, `// TODO also cross-cutting`,
  `// TODO refine` (on `clean:x` script), `// TODO 1D re-activate tabset (not in Warp) ...` — all self-documented, no
  action needed beyond tracking.
- **G10-P4-02 (Nit)** — Version override comments are informative and correct context (`fraction.js: "^4"` pinned
  because v5+ switched to BigInt/not JSON-safe without superjson; `typescript: "^6"` pinned pending a switch away from
  parse-ts-import) — flagged only as a positive note, not an issue.

No other issues found in the `_static_files()` README-generation logic.
