# Manage Dependencies

Manage dependencies conservatively. Prefer the repo's existing packages and tooling over adding new external packages.

This monorepo uses the "pnpm" package manager

## Dependency Policy

- Prefer as few dependencies and transitive dependencies as practical.
- Prefer isomorphic packages when the code may run in multiple environments.
- Prefer ESM-compatible packages from reputable maintainers.
- Avoid adding a dependency for small utilities that can be expressed clearly with local code.
- If a commonly used external package is necessary, consider wrapping it behind a thin semantic local layer.
- Treat intentionally outdated dependencies as intentional. `sharp` is intentionally constrained because of Parcel.

## IMPORTANT

This monorepo has a dedicated tool to automatically generate and maintain all the root files of a package: package.json,
tsconfig.json. You can edit them, but your edits may be overwritten anyway.

## Adding A Dependency

Do NOT edit package.json. This is useless since it's autogenerated by a tool. Instead, just use the dependency in the
code. The tool will later pick it up and update package.json automatically.

## Updating dependencies

Do NOT do it. This it done automatically by the tool which pick the latest major unless exception. If you need an
upgrade, ask the human.

## Removing dependencies

Not needed. Just no longer use the dependency. The tool will later auto-clean it.

## If a dependency is missing

Ask the human to run the magic tool.
